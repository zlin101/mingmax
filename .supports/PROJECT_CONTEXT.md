# PROJECT_CONTEXT.md

## 项目背景

mingmax 是一个面向 Agent 的综合分析项目。当前 v0.1 只聚焦「紫微斗数 + LLM Agent 分析」闭环，不扩展八字、MBTI、大五人格、多体系交叉验证、用户系统、支付系统、复杂前端、向量数据库、任务队列或复杂多 Agent 框架。

核心分工：

```text
程序负责算准，LLM 负责讲透，Agent 负责组织分析流程、追问与校准。
```

## v0.1 目标

v0.1 需要交付一个小而清晰、可测试、可替换的 Python 后端骨架，支持：

- 出生信息输入；
- 程序化紫微排盘入口封装；
- 命盘标准化为内部结构；
- 基于 LLM 的紫微语义分析；
- 主题分析；
- 宫位交叉验证；
- 追问问题生成；
- Markdown 报告生成。

## 当前仓库状态

截至当前梳理，仓库处于初始化阶段：

- `AGENTS.md` 已定义项目顶层约束；
- `pyproject.toml` 只包含基础项目元数据；

- 本轮补齐规范文档路径，不删除旧空文件。

## 角色分工

- Claude：负责后续开发和测试执行。
- Codex：负责 code review 和验收，不参与测试执行。
- LLM：只解释结构化命盘，不负责排盘、历法换算、安星、定宫、四化、大限或流年计算。

## 范围边界

v0.1 不实现：

- 八字模块；
- MBTI 模块；
- 大五人格等其他测评；
- 多体系交叉验证；
- 用户系统；
- 支付系统；
- 复杂前端；
- 向量数据库；
- 任务队列；
- LangChain、LangGraph、CrewAI 等复杂 Agent 框架。

## 输出安全边界

所有分析输出必须克制、可解释、可追问。不得使用绝对化、恐吓式、宿命论表达。报告必须包含免责声明：

> 本分析仅供文化研究、娱乐体验与自我反思参考，不构成医学、法律、财务、心理诊断或人生决策依据。
